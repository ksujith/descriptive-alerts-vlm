# Descriptive Alerts — LoRA fine-tuning of Qwen2-VL-2B on Charades

Turn a short home-video clip into one useful sentence:

> **motion detected** → **"A person is closing a door."**

This is the task behind consumer camera *descriptive alerts*. The repo
fine-tunes [`Qwen/Qwen2-VL-2B-Instruct`](https://huggingface.co/Qwen/Qwen2-VL-2B-Instruct)
with LoRA on [Charades](https://prior.allenai.org/projects/charades) — crowd-acted
everyday household activity, filmed in real homes, which is about as close as
public research data gets to indoor camera footage.

It is built to be *checkable*: the baseline is given a fair shot, the ablation is
properly controlled, the splits are actor-disjoint, and the failure taxonomy is
derived from the label structure rather than from eyeballing outputs.

> **Status:** pipeline complete and tested (30 unit/regression tests). Training
> runs on a free Kaggle T4 via `notebooks/train_kaggle.ipynb`. Result tables in
> `reports/RESULTS.md` are generated by the eval scripts — this README does not
> hand-copy numbers.

## Why the measurement design is most of the work

Fine-tuning a 2B VLM on 14k clips is routine. Getting a number you can defend is
not. Four decisions do the heavy lifting.

### 1. The baseline gets a fair chance

A stock VLM asked *"describe this video"* writes a paragraph. Scored against a
one-line target it earns ~0 BLEU — but that measures **output format**, not
perception. Reporting that as the baseline inflates the fine-tune's apparent
gain. So the base model is evaluated in four arms:

| Arm | Prompt |
|---|---|
| `open` | "Describe the main activity happening in this video clip." |
| `formatted` | + an explicit one-sentence `A person is …` constraint |
| `fewshot` | + three worked format examples |
| `choice` | forced choice over all 157 Charades class names |

The headline comparison uses `formatted` for **both** models — same prompt, same
frames, same decoder. The spread across arms is reported so you can see how much
of any gap was ever about format.

### 2. Charades is multi-label, so one accuracy number lies

A test clip carries **~4.3 other annotated actions** on average. A model that
says *"drinking from a cup"* on a clip labelled *"holding a cup"* is usually
right about the video and wrong only about which label the annotator attached.
So every table reports:

- **strict** — matched the clip's own class
- **lenient** — matched that class *or* any genuinely co-occurring action
- **verb / object accuracy** — partial credit via Charades' own
  157 = 33 verbs × 38 objects decomposition
- **macro-F1** — because the class set is imbalanced even after capping

### 3. The frame ablation is controlled, not just cheap

Each clip is decoded **once** at its maximum frame budget. The 1/4/8/16-frame
arms *stride that same cache*, so they see byte-identical pixels and differ only
in temporal density. Re-decoding per arm would also vary JPEG quantisation and
seek behaviour — confounding the thing being measured. Verified: striding 16→8
reproduces the 8-frame geometry exactly (`video_grid_thw=[4,22,30]`, 660 visual
tokens).

### 4. Splits are actor-disjoint, and that is asserted in tests

The official Charades test split shares no subject and no video with train
(verified: 0 overlap on both). Validation is carved out of train **by subject**
to preserve that property, so no actor leaks across the boundary. A test asserts
all three pairwise checks on every build.

## Results

Generated by `scripts/04_report.py` into **[`reports/RESULTS.md`](reports/RESULTS.md)**,
with the raw numbers in `reports/results.json`. Nothing is transcribed by hand.

The report contains: the headline baseline-vs-fine-tuned table, the four
baseline prompt arms, the frame-count ablation, the failure taxonomy breakdown,
and sampled generations per failure bucket.

## Failure taxonomy

Every prediction lands in exactly one bucket, assigned by a fixed-precedence
cascade. Categories come from the label structure, not from vibes.

| Bucket | Meaning |
|---|---|
| `correct` | Mapped to the clip's own annotated class. |
| `cooccurring_action` | Named a different action genuinely present in the window. **Not** counted as a perception failure. |
| `right_verb_wrong_object` | "putting a book" for "putting a cup". |
| `right_object_wrong_verb` | "drinking from a cup" for "holding a cup". |
| `related_both_wrong` | A real class, but verb and object both wrong. |
| `unmatched_prose` | Fluent, plausible, unmappable to any of the 157 classes. |
| `format_violation` | Broke the one-sentence contract. |
| `degenerate` | Empty, repetition loop, or refusal. |

Precedence is **content-first**: a right-but-malformed answer counts as
`correct`, and format compliance is reported as a separate orthogonal rate.
Summing shape errors into perception errors would hide which defect you have.

## Quickstart

Data prep runs on a laptop (CPU/ffmpeg). Training needs a CUDA GPU — Apple
Silicon cannot train this (no `bitsandbytes`, and MPS breaks Qwen2-VL's M-RoPE
path), but it handles every other step comfortably.

```bash
git clone https://github.com/ksujith/descriptive-alerts-vlm
cd descriptive-alerts-vlm
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e '.[eval]'
```

### 1. Get Charades (you accept its licence)

```bash
curl -L -o data/raw/Charades.zip \
  https://ai2-public-datasets.s3.amazonaws.com/charades/Charades.zip
unzip -q data/raw/Charades.zip -d data/raw/        # 3.5 MB annotations
./scripts/00_download_videos.sh                     # 16.3 GB, resumable
unzip -q data/raw/Charades_v1_480.zip -d data/raw/
```

### 2. Build the clip manifest and decode frames

```bash
python scripts/01_build_manifest.py          # -> data/interim/clips.csv
python scripts/02_extract_frames.py          # -> data/frames/  (resumable)
```

Train/val decode at 8 frames, test at 16; the ablation strides those caches.

### 3. Train on a free Kaggle T4

```bash
python scripts/05_pack_for_kaggle.py --username YOUR_KAGGLE_USERNAME
kaggle datasets create -p data/kaggle_upload --dir-mode skip   # stays PRIVATE
```

Then open `notebooks/train_kaggle.ipynb` on Kaggle, attach that dataset, set the
accelerator to GPU, and run. Every expensive cell is skip-if-exists and training
resumes from the newest checkpoint, so a session timeout is not a restart.

Locally, if you have a CUDA box:

```bash
python -m dalerts.train --config configs/smoke.yaml          # 16 samples, sanity
python -m dalerts.train --config configs/t4_8frame.yaml       # the real run
```

### 4. Evaluate and report

```bash
A=runs/t4_8frame/adapter
C="--split test --batch-size 4"
python scripts/03_generate.py $C --arm formatted --n-frames 8 --tag baseline
python scripts/03_generate.py $C --arm formatted --n-frames 8 --tag ft --adapter $A
for n in 1 4 16; do
  python scripts/03_generate.py $C --arm formatted --n-frames $n --tag ft --adapter $A
done
for arm in open fewshot choice; do
  python scripts/03_generate.py $C --arm $arm --n-frames 8 --tag baseline
done
python scripts/04_report.py
```

### 5. Publish the adapter

```bash
python scripts/06_push_to_hf.py --adapter $A \
  --repo-id YOUR_HF_USERNAME/qwen2vl-2b-charades-alerts-lora --dry-run
```

The model card is **generated from `reports/results.json`**, so its numbers
cannot drift from the run that produced them. Uploads are allowlisted to the
adapter, processor config, card and result tables — no frames, ever.

## Training setup

| | |
|---|---|
| Base | `Qwen/Qwen2-VL-2B-Instruct` (2.2 B, 28 LM layers + 32-block ViT) |
| Adapter | LoRA r=16, α=32, dropout 0.05 on **196** LM linear layers; ViT frozen |
| Precision | fp16 base, **fp32 LoRA params** (fp16 trainables crash `GradScaler`) |
| Attention | `sdpa` (FlashAttention-2 needs SM 8.0+; T4 is SM 7.5) |
| Loss | response tokens only — ~8 of ~750 tokens per sample |
| Frames | 8 uniform at ≤256 tokens/frame → ~660 visual tokens |
| Batch | 1 × 8 grad-accum, cosine schedule, lr 1e-4, 2 epochs |

Qwen2-VL pairs video frames temporally (`temporal_patch_size=2`), so 16 frames
costs ~1320 visual tokens rather than the ~6k a naive estimate suggests. That is
why the 16-frame arm fits a 16 GB T4 at all.

### Data

| Split | Clips | Videos | Subjects | Classes |
|---|---|---|---|---|
| train | 13,994 | 5,664 | 175 | 157 |
| val | 601 | 407 | 20 | 157 |
| test | 1,551 | 981 | 45 | 157 |

One clip per annotated action segment, windowed to 2–10 s. Per-class capping
takes the native **58×** class imbalance down to ~5×. Timestamps are clamped
into the real video extent first — the raw CSVs contain negative starts and ends
past the video duration.

Charades always has 480 as the *long* side and ~27% of clips are portrait
(480×270 as well as 270×480). Frames are stored at short side ≤ 308 without
upscaling, so every frame lands in a 160–185 visual-token band regardless of
orientation — predictable memory, and the processor never has to downscale.

## Tests

```bash
pytest
```

Covers the bugs this pipeline actually hit, which is the useful kind of test
suite:

- three slash-compound class names kept a stray capital (`watching/Looking`)
- `on` vs `at` as stopwords collapsed *"Sitting on a table"* and *"Sitting at a
  table"* into one label — silently corrupting strict accuracy
- BLEU-4 returned **0.0 for identical captions**, because the label-matching
  tokenizer stripped the sentence lead and left no 4-grams
- repetition loops (`"holding holding holding"`) scored as clean answers
- batched generation needs **left** padding; the tokenizer defaults to right

## Limitations

- Charades is crowd-acted, mostly single-actor, handheld or tripod. Real
  fixed-mount footage differs in angle, lighting and compression — expect a
  domain drop.
- Closed label space: unfamiliar activities get described with the nearest known
  class rather than an abstention.
- One action per clip, though clips genuinely contain several.
- No audio, no person re-identification, no temporal localisation.
